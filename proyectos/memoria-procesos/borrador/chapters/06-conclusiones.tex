\chapter{Conclusiones y Trabajo Futuro}
\label{cap:conclusiones}

\section{Conclusiones}

El proyecto \textit{La Grada Colchonera} ha permitido cumplir con éxito tanto el objetivo principal como la totalidad de los objetivos específicos formulados en el Capítulo~\ref{cap:introduccion}, combinando la construcción de una aplicación web completa y funcional con la aplicación rigurosa de las disciplinas de la Ingeniería del Software:
\begin{itemize}
    \item \textbf{Cumplimiento del objetivo principal:} Se diseñó, implementó, verificó y desplegó en producción sobre Google Cloud Run un sistema SaaS en capas con gestión segura de usuarios y un videojuego interactivo web \textit{survivor} en pixel art, cuyo progreso y marcas se consolidan de forma fidedigna y persistente en el servidor.
    \item \textbf{Arquitectura desacoplada y modular (Objetivo específico 1):} La estricta separación entre la presentación web, el cliente de API (\texttt{api.js}), las rutas HTTP en Express 5, la lógica de negocio (\texttt{src/services}) y los repositorios de datos permitió desarrollar el Sprint 1 y añadir la lógica completa del juego en el Sprint 2 sin desestabilizar la infraestructura previa, verificando la portabilidad entre memoria y PostgreSQL.
    \item \textbf{Gestión de identidades y seguridad por diseño (Objetivo específico 2):} Se implementó un subsistema robusto con contraseñas derivadas mediante \texttt{bcrypt} (coste 10), confirmación transaccional con tokens HMAC-SHA256, autenticación externa con Google OAuth 2.0 (RFC 6749), sesiones respaldadas en base de datos y autorización por roles (\textit{user} y \textit{admin}) con protección estricta del último administrador.
    \item \textbf{Persistencia relacional e integridad (Objetivo específico 3):} El esquema relacional en PostgreSQL sobre Neon gestiona de forma transparente el ciclo de vida de usuarios, sesiones y clubes mediante cinco migraciones SQL versionadas, incorporando índices únicos parciales para posibilitar el retorno de usuarios tras una baja voluntaria.
    \item \textbf{Lógica del videojuego y equidad anti-trampas (Objetivo específico 4):} El motor determinista de paso fijo (60 Hz) garantiza partidas justas e independientes del hardware, mientras que el servidor valida las partidas finalizadas contrastando los tiempos reales de juego con límites estadísticos admisibles, actualizando el club bajo concurrencia optimista.
    \item \textbf{Disciplina metodológica y CI/CD (Objetivo específico 5):} La metodología Scrum articulada en DoneTonic (48 PBIs y 82 tareas cerradas) y el flujo GitHub Flow con integración continua en GitHub Actions aseguraron que cada cambio incorporado a \texttt{main} cumpliese la Definición de Hecho y se desplegase automáticamente en la nube.
    \item \textbf{Verificación sistemática (Objetivo específico 6):} Se alcanzó una suite de 276 pruebas automáticas sobre \texttt{node:test} que evalúan exhaustivamente tanto los caminos felices como los escenarios de error, complementada con la auditoría frase a frase frente a las directrices de la asignatura.
\end{itemize}

\subsection{Lecciones aprendidas}

El desarrollo del proyecto aportó valiosas enseñanzas metodológicas y técnicas:
\begin{enumerate}
    \item \textbf{Granularidad de tareas y control de flujo:} Descomponer los requisitos en tareas técnicas breves asociadas a ramas y pull requests individuales previene discrepancias de integración y facilita la detección temprana de anomalías.
    \item \textbf{Automatización del despliegue desde fases tempranas:} Disponer de un pipeline de CI/CD operativo desde el inicio del proyecto reduce la incertidumbre en las entregas y evita sorpresas de configuración en el entorno productivo.
    \item \textbf{Pruebas prioritarias de casos de error:} Enfocar la verificación en las condiciones de contorno y rechazo (claves duplicadas, sesiones expiradas, resultados inverosímiles) genera una base de código más resiliente que limitarse al camino nominal.
    \item \textbf{Verificación visual y funcional continua:} Las pruebas de extremo a extremo y las revisiones manuales en navegador resultan indispensables para identificar fallos de experiencia de usuario sutiles, como el desplazamiento de botones tras mensajes de validación.
\end{enumerate}

\section{Trabajo futuro}

Para la evolución posterior de \textit{La Grada Colchonera} se proponen las siguientes líneas de trabajo:
\begin{enumerate}
    \item \textbf{Multijugador cooperativo en tiempo real:} Implementar un subsistema multijugador síncrono que admita grupos de juego (\textit{parties}) de hasta 4 jugadores simultáneos sobre WebSockets, gobernados por un servidor autoritativo que sincronice la simulación del mundo.
    \item \textbf{Ampliación de contenidos y clasificación por temporadas:} Diseñar nuevos personajes, jefes mayores y equipaciones históricas, complementando el ranking actual con clasificaciones periódicas por temporadas competitivas y por ambiente alcanzado.
    \item \textbf{Recuperación de credenciales y limitación de tasa (\textit{rate limiting}):} Incorporar el flujo de restablecimiento de contraseñas por correo electrónico y añadir protección perimetral frente a ataques de denegación de servicio o fuerza bruta mediante limitadores de peticiones por dirección IP.
    \item \textbf{Pruebas de extremo a extremo automatizadas y PWA:} Integrar tests automatizados de interfaz con Playwright en el flujo de CI para medir la cobertura de código en cliente, y empaquetar el juego como aplicación web progresiva (\textit{Progressive Web App}, PWA) instalable en dispositivos móviles.
\end{enumerate}
